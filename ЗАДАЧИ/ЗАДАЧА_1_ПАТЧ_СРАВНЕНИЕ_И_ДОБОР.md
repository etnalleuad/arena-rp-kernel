# ЗАДАЧА №1 АГЕНТУ: патч из мёртвого сеанса — сравнить с main, взять ТОЛЬКО новое, структурировать (14.09.2026)

Скопируй целиком первым сообщением в чат агента с доступом к репо etnalleuad/arena-rp-kernel.

Контекст: в корне main лежат части патча закрытого сеанса arena/01a09170 (раунды 11–17): «последний патч.txt» и «последний патч (1).txt» (~13,2 МБ каждая). Патч — полный diff рабочей ветки того сеанса против старого base; примерно 90% его содержания УЖЕ в main через позднейшие консолидации. Ты курьер и архивариус, не редактор: тексты канона не переписываешь ни словом.

## ШАГ 0 — страховка
1. Запиши HEAD main; создай и запушь ветку backup/pre_patch_<дата>; не удаляй её никогда.
2. Опись всех файлов main с размерами и sha256 → `03_ИССЛЕДОВАНИЕ/checksums_pre_patch_<дата>.txt` (checksums_14_09.txt не трогай).

## ШАГ 1 — собрать патч из частей
1. Склей части в рабочий файл ВНЕ main (в своём воркспейсе): patch_full.diff. Порядок частей определяй по структуре патча: часть, начинающаяся серединной строкой hunk-а (@@ без заголовков файлов) — продолжение; проверяй чередование заголовков ---/+++/@@.
2. После склейки: `git apply --check patch_full.diff`. Не прошло — поменяй части местами, проверь снова. Не прошло ни в одном порядке — НИЧЕГО не применяй, в отчёт: какие hunk-и ломаются и на какой строке.
3. Патч — транспортная тара, а не канон: применяй его не вслепую, а как источник для сравнения (ШАГ 2).

## ШАГ 2 — сравнить и взять только новое (дубли НЕ создаём)
Для каждого файла и hunk-а патча:
1. Проверь, есть ли это содержание УЖЕ в main (дословно и по сути: grep ключевых строк, разделов, цифр, цитат).
2. Есть → пропускай; в отчёт строкой «уже в main: <файл/раздел>».
3. Нет (новые факты, раунды, файлы, правки) → извлеки в нужную папку по структуре: канон → `01_КАНОН_ИГРА/` и `02_ЯДРО_СИСТЕМЫ/`; исследование → `03_ИССЛЕДОВАНИЕ/` и `03_ИССЛЕДОВАНИЕ/sources_2026/`; архивные заметки → `06_АРХИВ_СТАРОЕ/`.
4. Контент-конфликт (патч говорит X, main говорит Y) — САМ НЕ РЕШАЙ: флаг в отчёт с цитатами обеих сторон и путями. Решает хозяйка.
5. Служебное из патча (kernel_view/, uploads/, logs/, research4/, image-search/, *.patch, *.diff, страницы доставки, дампы мышления) — в main НЕ нести.

## ШАГ 3 — уборка корня
1. После извлечения перенеси обе части патча в `06_АРХИВ_СТАРОЕ/archive/` с пометкой в `ИТОГОВЫЙ_АРХИВ_ОБНОВЛЕНИЙ.md` (что, откуда, почему).
2. В корне main держим только: README.md, НАВИГАЦИЯ.md, НОВЫЙ_ЧАТ_ПАКЕТ.md, ПЕРВОЕ_СООБЩЕНИЕ_чат6_OOC.md, СВОД_КАНОН_14_09.md, хроно чат 5.txt, хронология_игры_до_переезда.md, полная хроно 4 чатов.txt (сырьё, временно — до разбора задачей №2, потом тоже в архив).
3. Больше ничего не удаляй и не перемещай.

## ШАГ 4 — пост-верификация (без неё сдача не принимается)
1. Контрольные маркеры grep по канон-файлам: «послезавтра пойду с тобой», «овершот в ливень на Патриарших», «900 км», «стол четвёрки в 19:00», «на память» + список хозяйки, если приложит. Всё найдено — ок; нет — стоп и показать.
2. Опись после против описи до: таблица «файл — действие (новое/изменено/перенесено/в архив/пропущено-дубль) — размер до/после». Непредусмотренных удалений = ноль.
3. checksums после → `03_ИССЛЕДОВАНИЕ/checksums_post_patch_<дата>.txt`.
4. Одной строкой обнови: НАВИГАЦИЯ.md, СВОД_КАНОН_14_09.md, ИТОГОВЫЙ_АРХИВ_ОБНОВЛЕНИЙ.md.

## ШАГ 5 — коммит и отчёт
